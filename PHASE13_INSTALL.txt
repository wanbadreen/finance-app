KIRA PHASE 13 — NOTIFICATIONS & PROACTIVE ALERTS
================================================

WHAT THIS BUNDLE ADDS
---------------------
1. In-app Notification Center with bell + unread badge.
2. Mobile More > Notifications entry.
3. Mark as read, mark all as read, dismiss, refresh.
4. Deep links from alerts to Recurring, Budgets, Goals and Insights.
5. Recurring alerts:
   - Due soon
   - Due today
   - Overdue
6. Budget alerts:
   - >=80% used
   - 100% reached
   - Over budget
7. Goal alerts:
   - Goal completed
   - Target date within 7 days
   - Progress materially behind expected pace
8. Cash-flow warning:
   - Upcoming 30-day recurring expenses may push projected balance below zero
9. Settings > Notifications preferences.
10. Push subscription support for supported browsers / installed PWA.
11. Server-side notification generation every 15 minutes through Supabase cron.
12. Test notification button.
13. Anti-duplicate dedupe keys in the database.
14. 90-day cleanup cron for old read/dismissed notifications.

SAFE INSTALL METHOD
-------------------
1. Extract this bundle somewhere OUTSIDE your finance-app folder.
2. Open VS Code at your normal finance-app root.
3. In the VS Code PowerShell terminal, run the installer by full path, e.g.:

   & "C:\Users\YOURNAME\Downloads\kira-phase13\apply-phase13.ps1"

   IMPORTANT: terminal current directory must be your finance-app root.

The installer:
- creates a timestamped backup of index.html + service-worker.js
- copies the new Phase 13 files into the correct folders
- adds the CSS link and JS module tag to index.html
- DOES NOT touch your current script.js, style.css or supabase.js

MANUAL INSTALL ALTERNATIVE
--------------------------
Copy these files into the project:
- phase13-notifications.js -> project root
- phase13-notifications.css -> project root
- public/service-worker.js -> replace project/public/service-worker.js
- supabase/migrations/20260914_phase13_notifications.sql -> project/supabase/migrations/
- supabase/functions/notification-dispatch/* -> project/supabase/functions/notification-dispatch/

Then add before </head> in index.html:

<link rel="stylesheet" href="/phase13-notifications.css">

And add before </body>:

<script type="module" src="/phase13-notifications.js"></script>

SUPABASE DATABASE SETUP
-----------------------
Open Supabase > SQL Editor and run:

supabase/migrations/20260914_phase13_notifications.sql

It creates:
- notification_preferences
- notifications
- push_subscriptions
- RLS policies
- authenticated grants
- notification cleanup cron
- notification dispatch cron every 15 minutes

It REVOKES anon access to the new notification tables.

EDGE FUNCTION
-------------
Deploy:

supabase functions deploy notification-dispatch --project-ref zuueyhjzlcmegpklpdcb --no-verify-jwt

JWT verification is intentionally OFF because the same endpoint is called by cron.
The function still protects itself:
- manual/test calls authenticate the user's Bearer token
- cron calls validate x-cron-secret against report_scheduler_config

WEB PUSH / VAPID SETUP
----------------------
The Notification Center works even without VAPID.
VAPID is only required for background browser/PWA push.

Generate a VAPID key pair on your computer:

npx web-push generate-vapid-keys

You will receive PUBLIC KEY + PRIVATE KEY.

NEVER commit the private key to GitHub.

Add to .env.local for local development:

VITE_VAPID_PUBLIC_KEY=YOUR_PUBLIC_KEY

Add the SAME public key in Vercel Production environment:

VITE_VAPID_PUBLIC_KEY=YOUR_PUBLIC_KEY

Add these Supabase Edge Function secrets:

VAPID_PUBLIC_KEY=YOUR_PUBLIC_KEY
VAPID_PRIVATE_KEY=YOUR_PRIVATE_KEY
VAPID_SUBJECT=mailto:appkira2026@gmail.com

Redeploy notification-dispatch after adding secrets.
Redeploy Kira on Vercel after adding VITE_VAPID_PUBLIC_KEY.

IOS NOTE
--------
In-app Notification Center works in Safari/PWA.
Background Web Push on iPhone requires Kira to be installed as a Home Screen web app and notification permission granted.

TESTING
-------
After installation + database migration:

npm test
npm run dev

Test this sequence:
1. Login.
2. Confirm bell appears in the top bar.
3. Open Settings > Notifications.
4. Save all default preferences.
5. Create / adjust a recurring item due soon -> Refresh notifications.
6. Create a budget and spending >= 80% -> Refresh notifications.
7. Create a goal with a target date within 7 days -> Refresh notifications.
8. Click an alert -> it should mark read and navigate to the correct page.
9. Mark all as read.
10. Dismiss an alert.
11. If VAPID is configured: enable Push notifications and press Send test notification.

IMPORTANT
---------
Do not grant INSERT/UPDATE privileges to the anon role.
Phase 13 keeps the existing Kira security model: users can only read/write their own notification rows through RLS.
